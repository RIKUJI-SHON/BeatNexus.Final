# BattlesPage PCフィルターサイドバー移行 実装計画書

- 作成日: 2025-10-03
- 作成者: 開発チーム (GitHub Copilot)
- 関連ドキュメント: `docs/BeatNexus.md`, `docs/design-specification.md`
- 対象機能: Battlesページ (PC表示) 左サイドバーおよびフィルターカードのレイアウト再配置

---

## 1. 背景と目的

現在のBattlesページでは、PC表示時の左サイドバーにログインユーザー用の情報カードを配置し、フィルターカードはメインコンテンツ列の最上部に表示されている。今回の要件では、PC表示で左サイドバーの既存コンテンツを削除し、代わりにフィルターカードを常設する。また、フィルターカードをスクロール追従（sticky）させ、モバイル表示では現状レイアウトを維持した上で同様にフィルターカードを追従させる。

目的は以下の通り:
- フィルター操作を常に手元に置き、投票・観戦導線を強化する。
- 左サイドバーの余剰スペースを有効活用し、PCでの情報密度を最適化する。
- 既存UIコンポーネントを再利用し、実装コストを抑えつつ統一感を維持する。

---

## 2. スコープ

### 2.1 対象ファイル
- `src/pages/BattlesPage.tsx`
- `src/components/battle/BattleFilters.tsx`
- 必要に応じて: `src/styles` or `src/index.css`（`sticky-sidebar` 等のユーティリティ確認）

### 2.2 非対象
- モバイル表示のフィルターボタン・機能自体の変更
- フィルター項目追加・削除などUI内容の改変
- `UserInfoCard` や `TabbedRanking` の機能・表示位置（PC右サイドバー、モバイルでの表示）は現状維持

---

## 3. 現状整理

- PC表示 (`lg` ブレークポイント以上):
  - グリッド構成 `lg:grid-cols-5`
    - 左: `lg:col-span-1`, `sticky-sidebar`, `UserInfoCard` (ログイン時のみ)
    - 中央: `lg:col-span-3`, フィルターカード + バトル一覧
    - 右: `lg:col-span-1`, `TabbedRanking`
  - フィルターカードは `BattleFilters` 内で `battle-card-simple` コンテナとして描画
  - スクロール追従は左サイドバー (`sticky-sidebar`) と右サイドバー (`sticky-sidebar-extended`) のクラスで実現
- モバイル表示 (`lg:hidden` 部分):
  - フィルターカードはメインコンテンツ内に表示 (現状維持要件)
  - `TabbedRanking` と `UserInfoCard` は別セクションで表示

---

## 4. 変更方針

1. PCレイアウトのみを変更し、`BattleFilters` を左サイドバー内に再配置する。
   - 既存の `BattleFilters` 呼び出しを `lg:hidden` 付きにしてモバイル専用の表示に限定。
   - 新たにPC専用 (`hidden lg:block`) の `BattleFilters` を左サイドバーへ追加。
2. 左サイドバーの旧コンテンツ (`UserInfoCard`) を削除。
   - ログインユーザー情報は引き続きモバイルセクションの `UserInfoCard` を利用。
3. `BattleFilters` コンポーネント側のスタイル調整。
   - サイドバー仕様に合わせ、最大幅や内部余白をレスポンシブで調整。
   - 既存UIを保持するため、新規スタイルはコンテナ側ラッパークラスで定義し、コンポーネント本体の大幅な改造は避ける。
4. スクロール追従の共通化。
   - 左サイドバーで `sticky-sidebar` または新規 `sticky` クラスを適用。
   - モバイルでも sticky を効かせるため、`BattleFilters` を包むラッパーに `sticky` + `top-*` クラスを追加。
   - 既存の `sticky-sidebar` がPC専用である場合は、汎用的なクラス（例: `filter-sticky-container`）を新設し、CSSでブレークポイントごとに適用。

---

## 5. 実装ステップ

1. **レイアウト再構成 (BattlesPage.tsx)**
   - 左サイドバー内の JSX を `UserInfoCard` から `BattleFilters` に差し替え。
   - 既存の `BattleFilters` 呼び出しを `lg:hidden` でモバイル専用とし、PC版との二重レンダリングに備えて状態を共有（現行ステートをそのままpropsで渡す）。
   - 必要に応じてグリッドの `col-span` を再調整（中央カラムを `lg:col-span-4` に拡張するか、既存の `lg:col-span-3` のまま余白を調整するかを検討）。
2. **sticky挙動の付与**
   - PC: 左サイドバーラッパーに `sticky-sidebar`（既存クラス）または `lg:sticky lg:top-24` 等を設定。
   - モバイル: フィルターセクションの親に `sticky top-[var(--header-height)]` 相当のクラス付与。ヘッダー高さを確認し、コンスタントでズレが出ないようにする。
3. **BattleFilters の幅調整**
   - サイドバー内で横幅が狭くなるため、`BattleFilters` 内の `max-w` や `mx-auto` をレスポンシブ条件付きで設定。
   - 必要であれば `className` を props として受け取れるように `BattleFilters` を拡張し、`BattlesPage` 側でラッパークラスを指定。
4. **副作用確認**
   - フィルター切り替え時の `setCurrentPage(1)` 等のロジックに重複レンダリングが影響しないか検証。
   - `sticky` による z-index 問題が無いか（カルーセル矢印などと重ならないか）をチェック。
5. **スタイル共通化**
   - `sticky` 専用クラスを共通CSSに追加する場合、`Tailwind` のカスタムレイヤーまたは `@apply` を使用。
   - 既存ユーティリティで対応可能なら新規CSS定義は不要。

## 6. 想定リスクと対策

| リスク | 内容 | 対策 |
| --- | --- | --- |
| 状態共有の二重レンダリング | PC/モバイルで `BattleFilters` を2回描画するため、イベントハンドラやフォーカス移動が予期せぬ挙動を生む懸念 | 見た目だけ差し替える。モバイル側は `lg:hidden`、PC側は `hidden lg:block` で一度に1つだけDOMに存在させる |
| sticky位置の競合 | ヘッダーやカルーセルと重なり、視覚的に被る可能性 | `top` の値を調整し、重なりそうな要素とz-indexを検証 |
| レイアウト崩れ | サイドバー幅に合わせたコンポーネント調整が不十分でUIが詰まる | 768px以上での表示幅を検証し、必要に応じて `gap` や `padding` を調整 |
| ユーザー情報カードの表示損失 | PCでユーザー情報が確認できなくなる | モバイルセクションでの表示を明記し、将来PC右サイドバー等で再配置する選択肢を記載 |

## 7. テスト計画

1. **ユニット／型検証**
   - `pnpm lint`
   - `pnpm typecheck`
2. **E2E/手動確認**
   - PC (≥1280px): 左サイドバーへフィルターが配置され、スクロール追従すること。
   - PC: バトル一覧をスクロールしながらフィルターチップを操作しても位置が維持されること。
   - モバイル (≤639px): 現行レイアウトと同等の見た目が維持され、スクロール時にフィルターが追従すること。
   - タブレット: 両方の挙動が問題なく切り替わるか確認。
3. **アクセシビリティ**
   - キーボード操作時に sticky によるフォーカス移動が不自然にならないか確認。
   - レイアウト変更後も `aria` 属性・ラベルが保持されていること。
