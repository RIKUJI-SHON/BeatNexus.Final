# 🚨 パスワードリセット問題 - 緊急診断・対応手順

## 現在の状況
- ユーザーが「パスワードリセットリンクが無効か期限切れです」エラーを受信
- メールテンプレート更新が反映されていない可能性

## 緊急診断手順

### 1. メールテンプレート更新確認
**本番Supabase**: https://supabase.com/dashboard/project/qgqcjtjxaoplhxurbpis/auth/templates

**確認項目**:
- Reset Passwordテンプレートの「Body」フィールド
- `{{ .ConfirmationURL }}` → `{{ .TokenHash }}` に変更されているか
- 保存が正常に完了しているか

### 2. 新しいメールでテスト
1. 新しいパスワードリセットを申請
2. **最新の**メールを確認
3. リンクの形式をチェック：

**期待される形式**:
```
https://beatnexus.app/reset-password?token_hash=...&type=recovery
```

**古い形式（問題）**:
```
https://qgqcjtjxaoplhxurbpis.supabase.co/auth/v1/verify?token=...&type=recovery&redirect_to=https://beatnexus.app
```

### 3. ブラウザコンソールでデバッグ
1. F12を押して開発者ツールを開く
2. Consoleタブを選択
3. エラーメッセージが表示される前にコンソールログを確認

**期待されるログ**:
```
=== RESET PASSWORD PAGE DEBUG ===
🔗 Direct link params: { tokenHash: true, type: "recovery" }
🔐 Verifying token_hash with Supabase...
✅ Token verified, session established
```

### 4. 一時的な回避策（緊急時）
もしメールテンプレート更新に時間がかかる場合：

**代替方法A**: 手動でURLを修正
1. 古い形式のメールリンクをコピー
2. URLから`token=`の値を取得
3. 手動で以下にアクセス：
   ```
   https://beatnexus.app/reset-password?token_hash=[TOKEN値]&type=recovery
   ```

**代替方法B**: 開発環境でテスト
1. 開発環境（localhost:3000）でパスワードリセットをテスト
2. 正常動作確認後、本番環境設定を再確認

## 根本原因の可能性
1. **メールテンプレート保存エラー**: Supabaseダッシュボードで保存時にエラー
2. **キャッシュ問題**: メールテンプレートの更新が反映されていない
3. **権限問題**: メールテンプレート編集権限が不足
4. **設定の優先順位**: 複数の設定が競合している

## 確実な解決手順
1. **Supabaseサポートに連絡**: メールテンプレートが正しく保存されているか確認
2. **別の管理者アカウント**でメールテンプレート更新を試行
3. **Supabase CLIでの設定**: ダッシュボード以外の方法でテンプレート更新

## 緊急度：最高
ユーザーがパスワードリセットを完了できない状況が継続中
