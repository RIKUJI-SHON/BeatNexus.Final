# BeatNexus 広告管理ガイドライン

**日時**: 2025-08-21  
**対象**: 運営チーム・広告運用担当者  
**システム**: シンプル広告システム

## 概要

BeatNexusのシンプル広告システムは「企業データ + 広告素材 + 配置設定」の3要素で構成されています。このガイドラインでは、実際の広告を作成・管理する際の手順と注意点を説明します。

## 広告作成の基本フロー

### Step 1: 広告主（企業）の登録

```sql
-- 1. 新しい広告主を登録
INSERT INTO advertisers (name, website_url, contact_email) VALUES
  ('企業名', 'https://company.example.com', 'contact@company.com');
```

**入力項目**:
- `name`: 企業名（重複不可）
- `website_url`: 企業公式サイトURL
- `contact_email`: 連絡先メールアドレス

### Step 2: 広告素材の作成

```sql
-- 2. 広告コンテンツを作成
INSERT INTO simple_ads (
  advertiser_id, 
  title, 
  description, 
  image_url, 
  click_url, 
  contract_start_date, 
  contract_end_date, 
  is_active
) VALUES (
  '広告主のUUID',
  '広告タイトル',
  '広告説明文',
  'https://example.com/image.jpg',
  'https://example.com/landing',
  '2025-08-21',
  '2025-12-31',
  true
);
```

**入力項目**:
- `advertiser_id`: Step 1で作成した広告主のUUID
- `title`: 広告見出し（最大50文字推奨）
- `description`: 広告本文（最大120文字推奨）
- `image_url`: 広告画像のURL（推奨サイズ: 400x300px）
- `click_url`: クリック時の遷移先URL
- `contract_start_date`: 広告配信開始日
- `contract_end_date`: 広告配信終了日
- `is_active`: 広告の有効/無効フラグ

### Step 3: 配置設定

```sql
-- 3. 広告を特定の場所に配置
INSERT INTO ad_placement_assignments (
  placement_id, 
  simple_ad_id, 
  priority, 
  is_pinned
) VALUES (
  '配置場所のUUID',
  '広告のUUID',
  100,
  false
);
```

**設定項目**:
- `placement_id`: 配置場所のUUID（利用可能な配置一覧は後述）
- `simple_ad_id`: Step 2で作成した広告のUUID
- `priority`: 優先度（数値が小さいほど優先、1-1000推奨）
- `is_pinned`: 固定表示フラグ（true=常に最優先で表示）

## 利用可能な配置場所

### アクティブな配置場所一覧

```sql
-- 配置場所の確認
SELECT key, description FROM ad_placements WHERE is_active = true ORDER BY key;
```

**主要配置場所**:

| 配置キー | 説明 | 推奨広告タイプ |
|---------|------|---------------|
| `ranking.top.banner` | ランキングページ上部バナー | バナー広告（横長） |
| `home.features.mid.inline` | ホームページ機能説明中間 | インライン広告 |
| `home.latest.before-list.infeed` | ホームページ最新バトル前 | インフィード広告 |
| `battles.list.after-3.infeed` | バトル一覧3件後 | インフィード広告 |
| `battles.list.after-10.infeed` | バトル一覧10件後 | インフィード広告 |

## 画像仕様・ガイドライン

### 推奨画像仕様

**基本サイズ**: 400x300px（4:3比率）
**ファイル形式**: JPEG, PNG, WebP
**ファイルサイズ**: 200KB以下推奨
**カラーモード**: RGB

### バリエーション対応

| 配置タイプ | 推奨サイズ | 備考 |
|-----------|-----------|------|
| バナー | 728x90px または 400x150px | 横長レイアウト |
| インフィード | 400x300px | 正方形に近い比率 |
| インライン | 300x200px | コンパクトサイズ |

### 画像コンテンツガイドライン

**✅ 推奨**:
- 明瞭で読みやすいテキスト
- ブランドカラーの活用
- 高解像度・高品質な画像
- シンプルで分かりやすいデザイン

**❌ 禁止**:
- 過度に刺激的な内容
- 誤解を招く表現
- 著作権侵害となる素材
- 不適切な内容（アダルト、暴力等）

## 文章作成ガイドライン

### タイトル（headline）

**文字数**: 15-30文字
**内容**: 商品・サービスの核心的価値
**トーン**: 魅力的で行動を促すもの

**例**:
- ❌ 「弊社の新サービスについて」
- ✅ 「作業効率10倍アップのAIツール」

### 説明文（description）

**文字数**: 40-80文字
**内容**: 具体的なベネフィット・特徴
**構成**: 問題提起 + 解決策 + 成果

**例**:
- ❌ 「様々な機能を搭載した便利なアプリです」
- ✅ 「月間1000時間の作業時間削減実績。直感的UIで誰でも簡単操作」

### CTAテキスト

**固定**: 「詳しく見る」（システム側で自動設定）

## 運用手順

### 日常的な確認事項

1. **広告の配信状況確認**
```sql
-- アクティブな広告の確認
SELECT 
  sa.title,
  adv.name as advertiser,
  sa.contract_start_date,
  sa.contract_end_date,
  sa.is_active
FROM simple_ads sa
JOIN advertisers adv ON sa.advertiser_id = adv.id
WHERE sa.is_active = true
ORDER BY sa.contract_end_date ASC;
```

2. **期限切れ広告の確認**
```sql
-- 期限切れまたは期限間近の広告
SELECT 
  sa.title,
  sa.contract_end_date,
  CASE 
    WHEN sa.contract_end_date < CURRENT_DATE THEN '期限切れ'
    WHEN sa.contract_end_date <= CURRENT_DATE + INTERVAL '7 days' THEN '期限間近'
    ELSE '正常'
  END as status
FROM simple_ads sa
WHERE sa.contract_end_date <= CURRENT_DATE + INTERVAL '7 days'
ORDER BY sa.contract_end_date ASC;
```

### 広告の更新・停止

```sql
-- 広告の停止
UPDATE simple_ads SET is_active = false WHERE id = '広告UUID';

-- 配信期間の延長
UPDATE simple_ads SET contract_end_date = '2026-03-31' WHERE id = '広告UUID';

-- 優先度の変更
UPDATE ad_placement_assignments SET priority = 50 WHERE simple_ad_id = '広告UUID';
```

## トラブルシューティング

### よくある問題と対処法

**問題**: 広告が表示されない
**確認項目**:
1. `is_active = true` になっているか
2. 契約期間内（`contract_start_date` ≤ 今日 ≤ `contract_end_date`）か
3. 配置設定（`ad_placement_assignments`）が存在するか
4. RLSポリシーが正しく設定されているか

**問題**: 配置が見つからない
**対処法**:
```sql
-- 利用可能な配置の確認
SELECT key, description, is_active FROM ad_placements ORDER BY key;
```

## セキュリティ・権限管理

### 必要な権限

- **広告閲覧**: `viewer` 権限
- **広告編集**: `ad_ops` 権限  
- **全権限**: `internal_admin` 権限

### データアクセス制限

RLS（Row Level Security）により、適切な権限を持つユーザーのみがデータにアクセス可能です。
