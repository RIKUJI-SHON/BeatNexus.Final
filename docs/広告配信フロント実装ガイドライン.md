# 広告配信 フロントエンド実装ガイドライン (2025-08-21 Draft)
作成者: GitHub Copilot  
参照: `docs/広告配信システム_要件定義_2025-08-20.md` / `docs/BeatNexus.md`

> 現在 (2025-08-21) 広告配信・計測は「サスペンドモード」です。ネットワーク配信やイベント計測を行わず、将来再開を前提に UI/挿入骨格のみ維持します。

## 1. 目的
UI への広告挿入ポイントとコンポーネント契約を統一し、将来バックエンド再開時に最小差分で有効化できる状態を保つ。

## 2. サスペンドモード挙動
`src/config/ads.ts` の `ADS_SUSPENDED=true` により `useAdServe` はネットワーク呼び出しをスキップし `noFill=true` を返却。`AdSlot` は `fallback` (例: `HouseAd`) を表示、または何も描画しません。

再開時は `.env` または Vite 環境変数で `VITE_ADS_SUSPENDED=false` を設定しビルド。Edge Function `/ad/serve` が有効化されれば自動で動的広告が表示されます。

## 3. コンポーネント構成
| コンポーネント / Hook | 役割 | 備考 |
|-----------------------|------|------|
| `AdSlot` | ビューポート到達時に広告取得 (サスペンド時: 取得せず) | variant, preloadMargin, fallback 支援 |
| `useAdServe` | クリエイティブ取得 + 状態管理 | サスペンド時 early return |
| `useAdImpressionObserver` | 50%+1s で impression 送信 | 現在無効 (token 無) |
| `useAdClickTracker` | CTA クリック送信 | 現在無効 (token 無) |
| `HouseAd` | NoFill / プレースホルダ | 将来 A/B テスト拡張余地 |
| `AD_PLACEMENTS` | 公式 placement レジストリ | 追加時ここを更新 |

## 4. Placement 命名規約
`<page>.<section|list>.<position>.<variant>` 形式。例: `battles.list.after-3.infeed`

| 要素 | 説明 | 例 |
|------|------|----|
| page | ページ識別 | home, battles, ranking |
| section/list | 論理セクション | list, features, latest |
| position | after-X / top / mid / before-list など | after-3, top, mid |
| variant | 表示形式 | infeed, banner, inline, sidebar, carousel |

## 5. 挿入戦略
1. リスト型 (Battles / Ranking): 既存配列へ仮想ノードを index 基準で挿入。`injectAdSlots()` ヘルパー利用推奨 (将来導入可)。
2. セクション間 (Home features → rankings): セクション間に `<AdSlot />` を直接配置。
3. バナー (ranking.top.banner): 主要コンテンツ直下に 1 枠のみ。レイアウトジャンプを避けるため高さ安定なコンテナ。
4. 深部 infeed 枠 (after-10 等): セッション深度計測用途。No Fill 時は collapse してスクロール阻害を回避。

## 6. Skeleton / レイアウト安定性
`AdSlot` は `loading` 中空 div を描画。CLS を避けるため、親側で最小高さ (例: banner 140px, infeed ~220px) を Tailwind かクラスで保持しても良い。

## 7. Fallback ポリシー
| Variant | 推奨 Fallback | 理由 |
|---------|---------------|------|
| infeed | null (collapse) or `HouseAd` | フィード連続性維持 / ジャンプ回避 |
| banner | `HouseAd` | 視認性高い枠を空白にしない |
| inline | `HouseAd` | コンテンツ間ギャップ埋め |
| sidebar | プラットフォーム Tips | 空白がレイアウト崩れになる |

## 8. 開発手順 (新規枠追加)
1. `src/config/ads.ts` の `AD_PLACEMENTS` にキー追加 (`active:false` で開始)。
2. 要件定義 27.x に追記しレビュー。
3. ページコンポーネントに `<AdSlot placementKey="..." />` を挿入 (適切な variant / fallback)。
4. デザイン QA: placeholder 高さ / レスポンシブ。
5. 将来配信再開時 `active:true` へ切替、必要なら HouseAd → 動的広告確認。

## 9. トークン再開時の差分作業チェックリスト
| 項目 | 対応 |
|------|------|
| Edge `/ad/serve` 復活 | 署名付き token 発行実装 / CORS 確認 |
| `useAdServe` file_url / image 対応 | クリエイティブ type ごとにメディア表示 |
| Impression Hook 有効化 | `ADS_SUSPENDED=false` で自動有効化 (token 存在時のみ送信) |
| Click Hook rate limit | 5s → 将来 Redis or server-side dedupe |
| HouseAd A/B | variant ローテーション実装 |

## 10. アクセシビリティ
| 項目 | 方針 |
|------|------|
| バッジ | `広告 / AD` テキスト (screen reader 読み上げ) |
| 画像 alt | headline か 'ad' フォールバック |
| CTA | 明示的なラベル / ボタン role |

## 11. テスト観点 (フロント)
| 観点 | チェック |
|------|--------|
| 遅延ロード | スクロール前に fetch されない (suspended 時 skip) |
| Fallback 動作 | サスペンド時に適切な HouseAd or collapse |
| CLS | Lighthouse CLS 0.1 未満 |
| i18n | バッジ / CTA 翻訳 (将来) |

## 12. 再開トグル手順
1. `.env` に `VITE_ADS_SUSPENDED=false` を追加。
2. Edge Functions `ad-serve`, `ad-track` をデプロイ。
3. ローカル再ビルド → 本番プレビューで 1 つの placement にテスト creative を設定。
4. Network devtools で `/ad/serve` 応答/latency 確認 (<200ms)。
5. Impression & Click 送信ヘッダ payload 確認後、残り placement 有効化。
