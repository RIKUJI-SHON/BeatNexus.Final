# アクセシビリティ改善計画書

- 作成日: 2025-10-08
- 参照ドキュメント: `docs/BeatNexus.md`, Google PageSpeed Insights レポート (2025-10-08 21:45 JST)

## 1. 背景と目的
`docs/BeatNexus.md` に記載された BeatNexus のビジョンは、世界中のビートボクサーとファンが安心して参加できる競技プラットフォームを提供することにある。アクセシビリティの課題はユーザー体験とブランド価値を低下させるため、WCAG 2.2 AA 水準を最低基準として、視覚・聴覚・運動・認知的多様性を持つユーザーが同等の操作性を得られる状態を目指す。本計画書は改善対象の整理と優先順位付け、実行ロードマップ、検証方針を定める。

## 2. 評価サマリ
| 指標 | モバイル | デスクトップ | 備考 |
| --- | --- | --- | --- |
| Lighthouse パフォーマンス | 42 | 40 | 大型画像とブロッキング CSS に起因。UX 体験にも影響。

| Lighthouse Best Practices | 100 | 100 | 仕様順守。アクセシビリティ改善に伴う退行に注意。
| Lighthouse SEO | 100 | 100 | 技術的 SEO は良好。アクセシビリティ改善で維持。

### 自動診断で検出された主な指摘
- ボタン／リンクに識別可能な名前が欠落
- `alt` 属性の重複または不適切な代替テキスト
- 背景色と前景色のコントラスト不足 (主にヒーローとボタン状態)
- 見出し階層の欠落・降順でない並び
- `<meta name="viewport">` に `user-scalable="no"` が存在しズームを抑制
- モーダル内でフォーカスが適切に制御されない疑い (手動検証要)
- オフスクリーン画像の遅延読み込み欠如により Screen Reader での読み上げ順が遅延するリスク

## 3. 現状課題の整理
| カテゴリ | 課題内容 | 影響範囲 | 優先度 |
| --- | --- | --- | --- |
| セマンティクス/ラベル | アイコンボタン (例: 投票済みバッジ、コメントモーダル呼び出し) に `aria-label` が不足。リンクもテキスト無しアイコンに依存。 | バトルカード、ナビゲーション、モーダル | High |
| 画像代替テキスト | プロフィール画像や広告画像が重複 `alt`、または視覚依存説明のみ。 | バトル一覧、ホームヒーロー、ニュース | High |
| カラー＆コントラスト | primary ボタン/テキスト (#3B82F6 等) が暗背景でコントラスト不足。ホバー状態で不十分。 | 全ページ | High |
| 見出し構造 | `h` タグがスキップされセクション理解が困難。 | ホーム、バトル詳細、ニュース | Medium |
| ズーム対応 | Viewport 設定によりユーザーズーム禁止。 | 全ページ | High |
| キーボード操作性 | モーダルでフォーカストラップ未実装疑い、Esc クローズ不確実。 | モーダル全般 | High |
| ライブ領域通知 | 投票完了、エラーなどのトーストに `aria-live` 属性がない。 | 投票体験、アカウント操作 | Medium |
| 動画/音声コンテンツ | バトル動画にキャプション、テキスト要約が未整備。 | バトル再生ページ | Low (別プロジェクト化) |

## 4. 改善方針とスコープ
1. **セマンティクス強化**: すべてのボタン／リンクに意味的テキストまたは `aria-label` を付与し、装飾アイコンには `aria-hidden="true"` を適用。リスト・カード構造を適切なランドマーク (`<main>`, `<nav>`, `<section>`) に整理。
2. **色とコントラストの再定義**: Tailwind トークンを見直し、WCAG 4.5:1 (通常文字) / 3:1 (太字/大文字) を満たす配色セットとトークン化。デザインシステム記載 `design-specification.md` を必要に応じ更新。
3. **ズームとレスポンシブ対応**: `<meta name="viewport">` の `user-scalable` を削除し、コンポーネントのレスポンシブ崩れを QA。テキストサイズ変更時の折り返し検証を計画。
4. **キーボード＆フォーカス管理**: モーダル、ドロップダウン、タブ、トーストでフォーカス遷移を設計。Focus Trap Hook を共通化し、開閉時の `aria-expanded` と `aria-controls` を整備。
5. **フィードバック通知**: 重要メッセージ（投票完了、フォームエラー）に `aria-live="polite"`、クリティカルエラーには `assertive` を適用。アニメーションは prefers-reduced-motion を尊重。
6. **メディアアクセシビリティ**: 主要バトル動画に字幕 (WebVTT) 生成を検討。短期的にはテキスト概要と勝敗情報を装備。
7. **テスト体制**: 自動 (eslint-plugin-jsx-a11y, axe-core) と手動 (Screen Reader: NVDA/VoiceOver、キーボード専用操作) を組み合わせ、毎スプリントで検証。

## 6. 実行ロードマップ
1. **キックオフ (Week 0)**: ステークホルダー合意、現状コードレビュー、主要画面のスクリーンショット収集。
2. **Sprint 1 (Week 1)**: P0 項目の実装・レビュー・QA。キーボード操作と Screen Reader の最初の回帰テストを実施。
3. **Sprint 2 (Week 2-3)**: カラーパレット、トークン、`prefers-reduced-motion` 対応。Lighthouse 再計測で A11y >= 95 を確認。
4. **Sprint 3 (Week 4)**: フォーム、エラーハンドリング、通知系補強。`aria-live`、フォームバリデーションメッセージを固める。
5. **Sprint 4+**: メディアアクセシビリティ拡張、字幕制作ワークフロー導入、CI 自動テストの安定化。

## 7. 検証と受け入れ基準
- **自動テスト**: `pnpm test:a11y` (axe-core 集約) の導入。Lighthouse CI のアクセスビリティスコア 95 以上を継続。
- **手動テスト**:
  - キーボードのみで主要フロー (トップ → バトル視聴 → 投票 → コメント投稿) を完遂できること。
  - Screen Reader (NVDA 最新版 + Chrome) で見出しジャンプ、ランドマーク移動、フォーム入力が期待通り動作。
  - 色覚シミュレータ (Chrome DevTools) で情報が色に依存しない。
- **文書化**: 変更点は `docs/design-specification.md` と `.cursor/docs/dev-rules/YYYY-MM-DD_accessibility.mdc` にログを残す。

## 8. リスクと対策
| リスク | 影響 | 対策 |
| --- | --- | --- |
| 色変更に伴うブランド毀損 | ブランド一貫性低下 | デザイナー承認プロセス、スタイルガイド更新 |
| フォーカス制御の不具合で UX 悪化 | 操作不能、離脱 | React コンポーネント単位でユニットテスト、Storybook での回帰テスト |
| 字幕整備の工数超過 | リリース遅延 | 優先バトルのみ先行対応、外部ツール (Whisper) 活用 |
| 自動テスト false positive | 開発の停滞 | ルールごとに許容閾値設定、CI ワークフローでオプトイン運用 |
