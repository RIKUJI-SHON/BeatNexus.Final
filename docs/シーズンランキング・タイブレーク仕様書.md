# シーズンランキング・タイブレーク仕様書

最終更新: 2025-08-15
適用範囲: DEV → 検証後に PROD
関連: docs/BeatNexus.md, docs/バトル終了・結果集計・レーティング計算システム仕様書.md

## 目的
シーズンランキングにおいて、同一の season_points の場合に投票率ベースのタイブレークで順位差をつける。表示時の負荷を避けるため、試合確定（アーカイブ）時に軽量な増分集計を行い、ランキング表示は単純JOIN+ORDERで高速化する。

## タイブレーク指標（優先順）
1. weighted_vote_share DESC（加重投票率 = total_votes_for / total_votes）
2. sum_margin_ratio DESC（差分率の累積 = Σ((for - against)/total)）
3. battles_played DESC
4. last_battle_at DESC
5. user_id ASC（完全安定化）

## データモデル
- テーブル: public.season_user_metrics（PK: season_id, user_id）
  - season_id uuid
  - user_id uuid
  - battles_played int default 0
  - total_votes_for int default 0
  - total_votes_against int default 0
  - total_votes int default 0
  - wins int default 0
  - losses int default 0
  - draws int default 0
  - weighted_vote_share numeric(6,4) default 0.0
  - sum_margin_ratio numeric(7,4) default 0.0
  - last_battle_at timestamptz
  - updated_at timestamptz default now()
  - index: (season_id, weighted_vote_share DESC), (season_id, sum_margin_ratio DESC)

## 更新ロジック
- 関数: public.update_season_vote_metrics_after_battle(p_archived_battle_id uuid)
  - archived_battles から該当試合を取得
  - player1, player2 それぞれについて for/against/total, 勝敗/引分, margin_ratio を算出
  - UPSERT で season_user_metrics を更新し、weighted_vote_share を再計算
  - 0除算回避（NULLIF(total,0)）

- トリガー: archived_battles AFTER INSERT
  - 新規アーカイブ時に自動で update_season_vote_metrics_after_battle を呼び出し

- バックフィル: public.recompute_season_vote_metrics(p_season_id uuid, p_truncate boolean DEFAULT TRUE)
  - 対象シーズンの season_user_metrics を削除（または上書き）し、archived_battles 全件から再集計
  - JSONで件数とプレビューを返す

## 表示
- VIEW: public.season_rankings_view（アクティブシーズン向け）
  - profiles と season_user_metrics を JOIN
  - profiles.is_deleted = false で除外
  - ORDER BY season_points DESC, weighted_vote_share DESC, sum_margin_ratio DESC, battles_played DESC, last_battle_at DESC, user_id ASC
  - DENSE_RANK() を付与して rank を算出

## 整合性と既存フロー
- 既存の complete_battle_with_video_archiving(), update_battle_ratings_safe(), update_season_points_after_battle() は変更不要
- トリガーでアーカイブ直後に集計を実施するため、フローの副作用は限定的
- バックフィルにより過去分も整合

## エッジケース
- 投票総数0は通常想定外。万一のときはその試合の ratio 計算をスキップ（0除算回避）
- 削除ユーザーは ranking 表示で除外（metricsは保持しても可）

## 運用
- DEVでマイグレーション→バックフィル→VIEW でのオーダー確認
- 問題なければ PRODに同手順適用
- 必要に応じて recompute を再実行可
