## 4. 技術選択 / 実装方針
| 項目 | 選択 | 備考 |
|------|------|------|
| トークン署名 | HS256 (初期) | シンプル・高速 / KEY rotation 後続課題 |
| キャッシュ | Edge Function 内 LRU (Map + TTL) | デプロイ再起動でクリア許容 |
| 重複防止キー | `${creative_id}:${placement_id}:${user_or_anon}:${type}` | 5s TTL (クリック), 30s TTL (impression) |
| Observer | IntersectionObserver  | threshold=0.5, 1s タイマー |
| HouseAd | 静的 JSON 定義 | CTR/A/B 実験後ダイナミック化 |

#### 13.1.2 RPC EXPLAIN 計測結果 (2025-08-21)
対象: `public.ad_serve_candidates`

計測シナリオ:
1. パラメータ (placement + user_id のみ: targeting null) / 生成済み impressions (user 5 / anon 45)
2. パラメータ (placement + user_id + country=JP + language=ja + device=desktop)

結果サマリ:
- 実行時間 (Execution Time):
  - シナリオ1: 0.343 ms
  - シナリオ2: 0.331 ms
- プランニング時間 (Planning Time):
  - シナリオ1: 1.540 ms (再利用後低下見込み)
  - シナリオ2: 5.904 ms (初回計測時 / キャッシュ暖気後低下)
- 使用インデックス: `ad_campaigns_status_idx`, `ad_placements_key_key`, `ad_flights_campaign_placement_idx`, `ad_creatives_campaign_id_idx`, `ad_events_user_time_idx`, `ad_events_creative_type_time_idx`
- JSON ターゲティング SubPlan 実行回数: 各1回 (countries / languages / devices) 影響 <0.02 ms 程度

所見:
- 現行スケールでは OLTP 要件 (p95<20ms) に十分な余裕 (サブミリ秒) がある。
- `total_imps` 集計部は `ad_events_creative_type_time_idx` を Bitmap Heap Scan→Hash Semi Join 経由で利用 (条件は type='impression' + flight_id in base)。大量件数化時に `type, flight_id` 専用インデックスが有効になる可能性。
- `user_today_imps` は `(user_id, occurred_at)` 系インデックス利用で問題なし。将来 `type` を条件に含むクエリが主となるため `(user_id, type, occurred_at)` も検討余地。

推奨 (将来 しきい値ベース適用):
```
-- ad_events 行数 (impressions) が ~100k 超過した段階で評価
CREATE INDEX CONCURRENTLY IF NOT EXISTS ad_events_type_flight_idx ON ad_events (type, flight_id);
-- さらにユーザー日次クエリ最適化が必要になった場合
CREATE INDEX CONCURRENTLY IF NOT EXISTS ad_events_user_type_time_idx ON ad_events (user_id, type, occurred_at);
```

モニタリング用クエリ例:
```

SELECT count(*) FILTER (WHERE type='impression') AS impressions_total FROM ad_events;
-- プラン確認 (定期)
EXPLAIN ANALYZE SELECT count(*) FROM ad_events WHERE type='impression' AND flight_id = '<sample-flight-uuid>';
```

## 14. E2E テスト計画 & 初期結果 (2025-08-21)
### 14.1 テストスクリプト / 手順 (開発環境)
1. anon_session_id 生成 (UUID v4)
2. Serve: `POST /functions/v1/ad-serve { placement, lang, device, anon }`
3. Impression: AdSlot IntersectionObserver (50% 1s) 自動送信 → `ad-track` (type=impression)
4. Click: CTA ボタン押下 → `ad-track` (type=click)
5. Dedupe: 同 token 再送 (impression 30s 内 / click 5s 内) → `AD_DUP_EVENT`
6. Expired: 120s 後同 token で送信 → `AD_TOKEN_EXPIRED`
7. Refresh: `REFRESH MATERIALIZED VIEW mv_ad_stats_daily;`
8. Stats: `select * from get_ad_stats('24h')` で最新 CTR 確認
